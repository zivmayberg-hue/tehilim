# Теилим для семьи

A family page showing each family member's Tehillim chapter by Hebrew age, plus a daily reminder message. Private and operational notes (who uses it, sending setup, roadmap) are in `CLAUDE.local.md`, which is never committed.

## Files
- `index.html` is the whole site (single file, the Psalms text is embedded), served by GitHub Pages from main, root folder. `og.jpg` and `apple-touch-icon.png` are the share preview and home-screen icon. `.nojekyll` turns off Jekyll.
- `sw.js` is the service worker that keeps the page working offline: the page and icon network first (with `cache: no-cache` and a 6-second fallback to the copy, so a new version loads the next time the page opens with internet), Google Fonts cache first, everything else (statistics) untouched. Live and preview have separate caches by scope. It registers only on https (and localhost for tests).
- Search engines: the page is kept out of search results by the noindex tags in `index.html` only. `robots.txt` in this repository is not at the domain root (the site is served under a subpath), so crawlers never read it; it protects nothing.
- `notify/notify.js` builds and sends the reminders; `.github/workflows/notify.yml` runs it five times each morning (06:13, 06:43, 07:13, 07:43, 08:43 UTC = 10:13 to 12:43 Dubai and 08:13 to 10:43 in Herzliya, Bucharest and Kyiv in winter, so nobody is woken early; several runs because GitHub often starts scheduled runs late) and installs `@hebcal/core` 5.8.0 at runtime. Runs are one at a time (concurrency group), each checks out the branch as it is when it starts, and the first run that starts sends; the rest find today's line in `notify/sent.log` and stop. The log push pulls first and retries.
- Admin alerts: only when the admin has to act, in English, only to the admin's private Telegram chat with @tehilim_mayberg_bot (`ADMIN_TG_CHAT_ID` if set, otherwise `TG_CHAT_ID`, which is that private chat; a negative id or the WhatsApp group id is refused), never to the family group; family messages stay Russian. Four kinds: (1) no successful `notify.yml` run today (Dubai date) by 12:13 Dubai: the Vercel cron `/api/check` (tehilim-trigger, 08:13 UTC) restarts `notify.yml`, then alerts directly from Vercel (so it arrives when GitHub Actions is down), saying whether GitHub accepted the restart; (2) WhatsApp disconnected: each `notify.js` run first asks Whapi `/health` (`AUTH` = connected); (3) every 10 days "open the bot's WhatsApp"; (4) the Vercel token 30 and 7 days before expiry (`github-authentication-token-expiration`); (3) and (4) come from `.github/workflows/alerts.yml` (dispatch only), which `/api/check` starts daily. If GitHub does not answer at all, `/api/check` alerts directly. Whenever today's family message did not reach WhatsApp (WhatsApp failed, the run was late, or no successful run by 12:13), the English alert is followed by a separate Telegram message with exactly the Russian family message, ready to forward; for (1) Vercel builds it with the same code (`index.html` and `notify/notify.js` from raw.githubusercontent.com, main, `@hebcal/core` 5.8.0, TZ Asia/Dubai), so `notify.js` must keep `buildMessage` and `C` exported and load `alerts.js` only inside the sending functions. `notify/alerts.log` (committed like `sent.log`) keeps each GitHub-side alert to once per problem per day; `sent.log` stops a restarted run from posting twice. `notify/alerts.js` holds the texts; `node notify/alerts.js test` and `/api/check?test=1` send one 🧪 test alert of each kind.
- The family list (`PEOPLE`) lives only in `index.html`; `notify.js` reads it from there.
- `notify/sent.log` and `notify/alerts.log` record sent reminders and alerts, prevents duplicate sends and keeps the GitHub schedule active. The workflow commits it to main, so always `git pull --rebase` before committing.
- `tests/` holds dev-only tests (see Tests). Nothing in it is loaded by the site or the workflow.
- The page is self-contained: only Google Fonts loads from outside, plus the statistics script on the live site and the family data API (below). Sun times are computed in the page with the NOAA equations (same as Hebcal). chabad.org is the reference for every time, on the page and in the messages: sunset and the end of Shabbat and Yom Tov (8.5°) rounded to the nearest minute; candle lighting = sunset to the nearest minute minus 18 minutes, or chabad.org's own value for that city in Israel (`CANDLE_MINS`: Herzliya 30, Tel Aviv 22); minor fasts start at dawn (16.9°, minute rounded down; where the sun never gets that low, as in Kyiv around midsummer, midnight), Tisha B'Av at sunset the evening before, Yom Kippur at candle lighting; fasts end at nightfall (6°, minute rounded up), Yom Kippur at the end of Yom Tov. The coordinates of the five reminder cities (and their time zones in `CITIES`) are those of chabad.org's city pages. `candlesOn`, `havdalahOn` and `spanTimes` in `index.html` are the one source of these times, used by the page and by `notify.js`. The weekly portions are an embedded table between the `PARSHA_TABLE` markers, generated by `tests/gen-parsha-table.js` from `@hebcal/core` 5.8.0 through the end of 2036; regenerate it with `NODE_PATH=tests/node_modules node tests/gen-parsha-table.js` (the tests fail when it has less than 12 months left).
- `notify.js` runs the part of the `index.html` script before `const RESULTS` in Node, so code there must not touch `document`, `window` or `location` without a `typeof` guard.
- "Прочитано" ticks: every person's psalm is read and marked separately, even when two people share a chapter. Ticks are stored only on the device in localStorage (`tehilim-ticks`, or `tehilim-preview-ticks` on the preview, since both sites share one origin), keyed by the Hebrew day, so they reset at sunset in the phone's city. Without storage they last for the visit. Nothing is sent anywhere.
- Statistics: Umami Cloud, website ID `deea2162-7faf-4852-80f9-dd5d77e49baa`, live site only. The page loads `https://cloud.umami.is/script.js` itself (with `data-auto-track="false"`) only on `/tehilim/` without `?date`, `?time` or `?tz`, never on the preview, and sends one page view per open plus the events `read` (each tick, not undo), `psalm` (with `chapter`) and `all`, each with `tz`. `?stats=off` turns statistics off on that device (localStorage `tehilim-stats-off`), `?stats=on` turns them back on. If Umami is blocked or slow the page works the same; nothing about statistics is shown on the page.
- Languages: Russian (default), English and Hebrew. The switch "RU · EN · עב" sits in its own row in the top right corner in every language (44 px buttons). The page opens in Russian unless this device chose a language (localStorage `tehilim-lang`, `tehilim-preview-lang` on the preview), or `?lang=ru|en|he` chooses and remembers it; the phone's language is never used. All texts are in `T` in `index.html` (the Russian strings are the original ones), cities in `CITY_NAMES`, family names in `PEOPLE` (`en`, `he`), groups in `GROUP_NAMES`, holiday, month and portion names as in Hebcal. Hebrew is right to left (`dir="rtl"`, iOS Hebrew system font, Hebrew dates in Hebrew numerals), times always left to right. Umami gets a `lang` event when a language is chosen. The WhatsApp reminder stays Russian only.
- Daily Tehillim ("Ежедневный Теилим", below the family cards): by day of the Hebrew month, Chabad division as on chabad.org (`MONTHLY`; on the 29th of a 29-day month 140-150; on the 25th and 26th Psalm 119 verses 1-96 and 97-176), and by day of the week (`WEEKLY`, Sunday 1-29 to Shabbat 120-150; the standard weekly division printed in Tehillim books, confirmed by the user, since chabad.org does not publish it). Both follow the Hebrew day, which changes at sunset in the phone's city. Each card has a tick (keys `daily-month`, `daily-week` in the same tick storage, not counted in "Прочитано N из 12") and opens all its chapters with headings. The reader remembers the place per reading and Hebrew day (localStorage `tehilim-pos`, `tehilim-preview-pos` on the preview), saved only after the reader scrolls himself, and offers "Продолжить с псалма N" (by verse inside 119).
- Reader: the screen stays awake while a psalm is open (Wake Lock, released on close; nothing if unsupported). A psalm opened from a card ends with "Следующий: имя, Псалом N" for the next card; after the last family member come the monthly and the weekly reading, then "Назад к списку".
- Sefirat HaOmer (card in `#banners`, `omerAt`, `omerHe`, `omerRu` in `index.html`): from sunset in the phone's city on the 49 evenings from the second night of Pesach (16 Nisan) to the night of 5 Sivan, tonight's count, "считать после выхода звёзд" (nightfall 6°, as fast ends), the blessing and the count in Hebrew (Chabad siddur as on chabad.org's Count Today's Omer, `tests/fixtures/chabad-omer.txt`; "שֶׁהֵם", "לָעוֹמֶר", no meteg), the meaning in Russian or English; until dawn the night version; by day until sunset "Если забыли вечером, считайте днём без благословения..." with the count only; always the note that after a whole missed day one counts without the blessing; Lag BaOmer marked on the 33rd. Sources: chabad.org Count-the-Omer.htm and article 136110 (How to Count the Omer).
- Who reads (Phase 7): each device knows its person, set once and kept only on the device (localStorage `tehilim-me`, `tehilim-preview-me` on the preview; "guest" for "Пропустить"). Personal links `?me=aron|natalia|yana|ziv|dafna|israel|polina|moshe` set the person and their language (Aron, Natalia, Yana Russian; Ziv, Dafna, Israel Aviah English; Polina, Moshe Hebrew) without asking, remember it and remove `?me=` from the address bar. Without a person, an iOS-style bottom sheet "Кто читает?" (Russian only, 8 name buttons in each person's own language, "Пропустить" = guest) slides up once per device; never in the reader, over a banner (Shabbat card, holiday or Omer card, Rosh Chodesh), on `?date/?time/?tz` links or without storage; "Сменить имя" at the very bottom reopens it. The greeting carries the person's name in the site language; a guest gets none; a device that has not chosen yet keeps the old "…, Арон". The RU/EN/עב switch still overrides the language.
- Family data API: `https://tehilim-trigger.vercel.app/api/family` (tehilim-trigger `api/family.js`, `lib/reading.js`, Vercel region fra1) over Upstash Redis "tehilim-db" (Vercel Marketplace, Free plan, Frankfurt; `KV_REST_API_URL`, `KV_REST_API_TOKEN`). The page posts a queue (localStorage `tehilim-outbox`, `tehilim-preview-outbox`; kept offline and sent later) and gets back who read today: under the count line "Сегодня: Арон 12/12 ✓ месяц ✓, Дафна 5/12" (named people with a tick today) and, from 3 days, the device person's streak "Арон читает 23 дня подряд 🔥" (Shabbat and Yom Tov without ticks don't break it). Ticks stay on the device as before; a named person's ticks (and today's ticks when a person is first set) also go to the API, a guest's never. All calls are in the background with a 4-second limit; with the API down the page is unchanged. Stored: person or "guest", Hebrew day, what was ticked or opened, language, city and country from Vercel's headers, and a random id the page makes for itself (to count devices); no IP, no fingerprint; everything expires after 13 months (396 days). The preview keeps its own data ("p:" keys). Finishing all 12 family psalms shows a short note ("Спасибо! Все псалмы на сегодня прочитаны 🤍") that goes away by itself.
- Own statistics (live site only, like Umami, off with `?stats=off`): page opens and psalm, daily and all-psalms opens, with person, language, city and country. Weekly summary to the admin's private Telegram (English) on Sundays at the 12:13 Dubai check: visits per day, devices, cities, languages, psalms opened vs the week before, and per person days opened, days read, psalms ticked and streak; one line if the database does not answer.
- Preview-only parameters: on `/tehilim-preview/` the page accepts `?date=YYYY-MM-DD&time=HH:MM&tz=Area/City`; the live site ignores them.

## Calendar rules (do not change without asking the user)
- The Hebrew day changes at sunset.
- Chapter = Hebrew age + 1.
- Birthday rules as in Hebcal: Adar of a non-leap year and Adar II go to the last Adar; Adar I stays Adar I (plain Adar in non-leap years); 30 Cheshvan, 30 Kislev and 30 Adar I move to the 1st of the next month when that day doesn't exist.
- Diaspora holidays. Fasts are moved off Shabbat as in Hebcal. Rosh Chodesh is announced once, on its first day.

## Location rules
- Anything location-based on the page (sunset switch, Shabbat and holiday times) must follow the city of the phone's time zone and show that city's name; never assume a fixed city on the page.
  - `CITIES` in `index.html` maps each common time zone worldwide (and the aliases iPhones report) to [latitude, longitude, Russian city name]; `Asia/Jerusalem` is Herzliya, with candle lighting 30 minutes before sunset as on chabad.org. An unknown time zone falls back to a longitude from the UTC offset and is labelled "ваше время".
  - The weekly portion follows the Israel schedule when the time zone is in `ISRAEL_ZONES`, the diaspora schedule otherwise. Holidays on the page always follow the diaspora rules, like the reminders.
- The reminders are different: the morning check runs on Dubai time, and the Shabbat block always lists the five fixed cities: Dubai, Herzliya, Bucharest, Kyiv, Chernivtsi.

## Reminder rules
- One message per morning, only when something starts that evening (birthday, Rosh Chodesh, holiday, fast, Shabbat).
- A late run still posts to the group, however late, until the first event in the message starts (the earliest of the five cities: candle lighting for Shabbat and Yom Tov, sunset for other evening events, dawn for minor fasts) and never once Shabbat or Yom Tov has started in any of the five cities (`lateCutoff`). After that the message does not go to the group; the user's Telegram gets the English alert "⚠️ Tehilim: today's reminder ran too late for the group: ... began at HH:MM Dubai time ..." and then the message itself, and it is logged so later runs stop. The feedback message goes until sunset in Dubai, the Omer evening message until midnight Dubai.
- Never post on Shabbat or Yom Tov (diaspora); announce on the last weekday before instead.
- Every Yom Tov night is announced (first and second days of Rosh Hashana, Sukkot, Pesach and Shavuot, Shemini Atzeret, Simchat Torah, the 7th and 8th days of Pesach) with candle lighting for the five cities as on chabad.org (`ytLines`; `tests/fixtures/chabad-yomtov.csv`): the first night 18 minutes before sunset (Herzliya 30); a second night or a night after Shabbat "после выхода звёзд" / "после исхода Шабата", from an existing flame, at chabad.org's "Candle Lighting after" time (the end time, 8.5°); a Friday night before sunset, with the time in the Shabbat block. Herzliya: no second day in Israel except Rosh Hashana ("в Израиле праздник уже закончился"). Yom Kippur keeps its fast lines.
- Shabbat block every Friday: candle lighting and havdalah as on chabad.org (18 minutes before sunset, Herzliya 30; 8.5 degrees); weekly portion in Russian with Hebrew, plus a note when Israel reads a different portion; at the end a link to the diaspora portion on ru.chabad.org (stable per-portion address, `PARSHA_AID` in `notify.js`), none when the reading is for a holiday.
- Hanukkah (Chabad custom: right after sunset; on Friday before the Shabbat candles; on Saturday night after havdalah): one block on the morning of the first night (merged with that day's other news): on a weekday the time after sunset for the five cities; on Friday (or Saturday night) one line pointing to the Shabbat times below, since they are the same; then the custom in one line; on each Friday of nights 2 to 8 one line in the Shabbat block ("Сегодня N-я свеча, зажечь до свечей Шабата."); on Fridays also the line that the candles must burn until half an hour after nightfall, so bigger candles; no other Hanukkah messages.
- Fasts: the message the morning before (or the last weekday before) lists start and end for the five cities. Fasts through the night (Tisha B'Av, Yom Kippur) name the day of start and end; weekend days by name ("в субботу"). When Tisha B'Av starts on Saturday evening, the message explains that the fast (moved to Sunday when 9 Av is Shabbat) starts at sunset while it is still Shabbat and that havdalah over wine is on Sunday night after the fast. A dawn that falls back to midnight reads "с полуночи (HH:MM)". When Purim starts right after the Fast of Esther, the Purim message says when the fast ends.
- Sending goes to WhatsApp or Telegram depending on repository settings; if WhatsApp fails, the user's Telegram gets "WhatsApp didn't send. Forward the next message to the family group." and then the message itself. Details in `CLAUDE.local.md`.

## Design rules
- Russian UI by default (English and Hebrew available), very large text with the "Крупнее" button, warm gold and iOS glass style, one obvious button per card.
- Must work in light and dark mode on iPhone and iPad (two columns on iPad).
- Hebrew text with nikud, no cantillation marks; words joined by a maqaf never break across lines.

- Sefirat HaOmer: an evening message at nightfall in Dubai (`node notify/notify.js evening`, `.github/workflows/evening.yml`, started by the Vercel trigger `/api/trigger?slot=evening`, which runs every 5 minutes from 14:00 to 16:55 UTC and starts it in the first 5 minutes after Dubai nightfall, 18:57 to 19:35 over the season, and 30 minutes later as a backup; GitHub schedules 15:43 and 16:13 UTC March to June as a further backup; same concurrency group as the morning; a run more than 10 minutes before Dubai nightfall does nothing) with tonight's count in Russian and Hebrew, nightfall for the five cities and the site link, only when neither that day nor that evening is Shabbat or Yom Tov (diaspora, so in none of the five cities). Otherwise the count goes into the last morning message before (Friday: Friday and Saturday night, "после авдалы"; the morning before Yom Tov: all its evenings, "после исхода праздника"). The morning message that carries night 1 (Erev Pesach, or Friday when Erev Pesach is Shabbat) announces the count. The evening message goes to the group until midnight Dubai; later only to the admin (English alert, then the message). `notify/sent.log` evening lines are "YYYY-MM-DD вечер Омер N" and never stop the morning run, nor morning lines the evening run. The Vercel check `/api/check?slot=evening` at 16:40 UTC (20:40 Dubai) restarts `evening.yml` and alerts the admin with the message to forward, as in the morning.
- Monthly feedback message ("Дорогая семья! Это ваш Теилим-бот 🤖...", `FEEDBACK` in `notify.js`, Russian and English, its own message): the first one on Tuesday 3 November 2026 (`FEEDBACK_LAUNCH`, its own message even when that morning has another), then from December 2026 the first Sunday morning of each month; if that morning is Shabbat or Yom Tov or has a family message, the next ordinary morning without one (`feedbackDay`). Logged as "YYYY-MM-DD отзыв YYYY-MM", once per month.

## Writing rules for messages
- Plain spoken Russian, no em dashes, never decline personal names in templates (use "имя: ..." constructions instead).
- Don't copy third-party texts (e.g. Chabad.org) into messages; link to them instead.

## Workflow
- Run all commands yourself; only ask the user to approve, sign in or paste a token.
- Before every publish, run the tests and show the result. Never change `index.html` or `notify.js` without running them.
- Never print secrets in full.

### The site and reminders are live: never publish untested changes to main
The website and the reminders are used by the family every day. Pushing to main publishes immediately (GitHub Pages serves `index.html` from main; the daily workflow runs `notify/notify.js` from main). Therefore:
- Never push changes to `index.html`, `sw.js`, `og.jpg`, `apple-touch-icon.png`, `notify/notify.js` or `.github/workflows/` directly to main.
- Do all such work on a separate branch.
- Website changes: publish the branch to the preview site for review: the separate public repository `tehilim-preview` on the same account (GitHub Pages on, main branch, root), containing the same site files (`index.html`, `sw.js`, `og.jpg`, `apple-touch-icon.png`, `.nojekyll`) plus a `robots.txt` that disallows all crawlers; `index.html` keeps the same noindex tags. Never put `notify/` or `.github/workflows/` in the preview repository (the reminder would run twice). Give the user the preview link and screenshots at iPhone and iPad size, light and dark.
- Reminder changes: show dry-run messages for representative dates instead (run `notify/notify.js` locally with `TODAY=YYYY-MM-DD DRY_RUN=1 TZ=Asia/Dubai` and `NODE_PATH=tests/node_modules`).
- Merge to main only after the user writes "approved" for that specific change. After merging, confirm the live files are byte-identical to what was approved.
- Changes to `CLAUDE.md`, `.gitignore` and `tests/` alone may go to main directly, since they don't affect what the family sees.

## Tests
Run all tests with one command from the repository root:

```bash
tests/run.sh
```

`tests/run.sh page` (or any part of a file name) runs a single group. The first run installs the pinned test-only packages (`@hebcal/core` 5.8.0, `playwright` 1.63.0 and headless Chromium) into `tests/node_modules`, which is git-ignored.

Hard time limits: 3 minutes per test file (4 for `page.test.js`, which clicks every button on 140 page loads) and 10 minutes for the whole suite (`tests/run-all.js`; each file also stops itself 10 s earlier through `reporter()` in `tests/lib.js`). A file over its limit is killed together with the browsers it started and shown as FAIL "timed out". Browser tests must end with `.catch(e => { console.error(e); process.exit(1); })`, never just `process.exitCode = 1`, because an open browser keeps Node running. Never wait on a background test run for more than 15 minutes: stop it and investigate.
